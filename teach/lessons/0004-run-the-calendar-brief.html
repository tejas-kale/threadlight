Issue #12 · Lesson 4

Run the Calendar brief safely

Win: generate a real brief and check its boundaries without exposing unrelated Calendars.

1. Run automated checks

swift test

Expected: six tests pass. Tests use controlled data, not your Calendar.

2. Ask for Calendar access

swift run threadlight --list-calendars

macOS asks whether Threadlight may read Calendars. On approval, the command prints each title and identifier. An identifier distinguishes Calendars that share a title.

3. Generate from one safe Calendar

swift run threadlight --calendar "PASTE-IDENTIFIER-HERE"

Expected output starts with Outcome: completed, followed by Markdown events and a line containing Calendar status and refresh time.

4. Check the rule

Create three temporary events in that Calendar:

  1. today;
  2. tomorrow at 09:59;
  3. tomorrow at 10:00.

Run the command again. The first two should appear. The 10:00 event should not: the window is half-open and ends at 10:00.

Permission recovery

If access is denied, the command reports Outcome: not completed. Change access in System Settings → Privacy & Security → Calendars.

Retrieval

Why paste an identifier rather than a Calendar title?

Reveal answer

Different accounts can contain Calendars with the same title. Selecting by identifier prevents accidental access to an unselected Calendar.

Primary source: Apple: requesting full event access.
